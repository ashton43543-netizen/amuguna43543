# 소곤소곤 학급회의

먼저 **각자 익명으로 쓰고**, 마감하면 **한꺼번에 공개**하고, **중간 결과 없이 투표**하는 학급회의용 웹앱입니다.

학급회의에서 처음 나온 의견이나 목소리 큰 친구의 의견으로 분위기가 쏠리는 문제를 줄이려고 만들었습니다.
로그인 없이 **참여 코드 6자리**만으로 휴대폰에서 바로 쓸 수 있습니다.

---

## 1. 회의는 이렇게 진행돼요

| 단계 | 사회자(선생님·반장) | 학생 |
| --- | --- | --- |
| ① 의견 쓰기 | 안건을 입력해 회의를 만들고 참여 코드(또는 QR)를 알려 줍니다. 제출 **인원 수만** 보입니다. | 코드로 입장해 익명으로 의견을 씁니다. 다른 사람의 의견은 볼 수 없습니다. |
| ② 한꺼번에 공개 | "마감"을 누르면 모든 의견이 **무작위 순서**로 동시에 공개됩니다. 비슷한 의견을 묶습니다. | 공개된 의견을 함께 봅니다. |
| ③ 투표 | 투표 인원 수만 보입니다. | 1인당 정해진 표 수(1~3표)만큼 투표합니다. 중간 결과는 아무도 볼 수 없습니다. |
| ④ 결과 | "투표 마감"을 누르면 결과가 공개됩니다. | 득표 그래프와 소수 의견을 함께 봅니다. |

## 2. 기능

**기본 기능**

- **회의 생성**: 안건을 입력하면 숫자 6자리 참여 코드가 만들어집니다.
- **익명 의견 제출**: 한 사람당 의견 1개. 마감 전까지는 고칠 수 있습니다.
- **동시 공개**: 마감하는 순간 모든 의견이 무작위로 섞여 한꺼번에 공개됩니다.
- **비슷한 의견 묶기**: 사회자가 카드를 골라 하나로 합칩니다. 원래 의견들은 묶음 안에 그대로 남아 누구나 펼쳐 볼 수 있고, 다시 풀 수도 있습니다.
- **익명 투표**: 1인당 1~3표(사회자가 정함). 한 번 투표하면 바꿀 수 없고, 투표 중에는 결과가 보이지 않습니다.
- **결과 화면**: 득표 막대그래프, 공동 1위 표시, **소수 의견 따로 모아 보기**(1위 득표의 절반 이하를 받은 의견).

**쏠림을 줄이려고 더 넣은 것**

- **사회자도 마감 전에는 의견을 못 봅니다.** 사회자가 먼저 보고 분위기를 만들 수 없게, 제출 인원 수만 보여 줍니다. (화면에서만 숨기는 게 아니라 서버 규칙으로 막습니다.)
- **투표 화면의 의견 순서가 학생마다 다릅니다.** 맨 위에 있는 의견이 표를 더 받는 효과를 줄입니다. (번호는 모두 같아서 "3번 의견"처럼 말로 가리킬 수 있습니다.)
- **생각 시간 타이머**: 사회자가 1·2·3·5분 타이머를 켜면 모두의 화면에 남은 시간이 보입니다. 먼저 낸 사람을 따라 쓰지 않고 각자 조용히 생각할 시간을 줍니다.
- **입장 잠그기**: 우리 반이 다 들어온 뒤 잠그면, 다른 기기로 한 번 더 들어와 표를 늘리는 것을 막을 수 있습니다. 참여 인원 수가 항상 보여서 반 인원과 맞는지 확인할 수 있습니다.
- **내 의견·내 투표 가려 두기**: 제출한 뒤에는 내용이 접혀 있어서 옆자리 친구가 화면을 봐도 보이지 않습니다.

**회의 진행을 편하게 하려고 더 넣은 것**

- **QR 코드·큰 코드 화면**: 교실 TV나 칠판 화면에 띄우면 카메라로 찍어 바로 들어옵니다.
- **부적절한 의견 가리기**: 욕설·장난 글은 사회자가 가릴 수 있습니다. 대신 **가린 개수는 모두에게 표시**되어 몰래 지울 수는 없습니다.
- **쓰던 글 자동 저장**: 휴대폰이 탭을 새로고침해도 쓰던 글이 남아 있습니다.
- **사회자도 참여**: 반장이 사회를 볼 때는 "나도 참여"를 눌러 의견을 내고 투표할 수 있습니다.
- **결과 복사**: 결과를 글로 복사해 회의록에 붙여 넣을 수 있습니다.

## 3. 내 컴퓨터에서 먼저 써 보기 (Firebase 프로젝트 없이)

Firebase 에뮬레이터(연습용 가짜 서버)로 돌려 볼 수 있습니다. 가입이나 설정이 필요 없습니다.

**준비물**

- [Node.js](https://nodejs.org/) 20 이상
- Java 21 이상 (Firestore 에뮬레이터가 사용합니다. [Adoptium](https://adoptium.net/)에서 받을 수 있습니다.)

**실행**

```bash
npm install     # 처음 한 번만
npm run dev
```

"All emulators ready!"가 나오면 브라우저에서 <http://localhost:5173> 을 엽니다.
화면 맨 위에 노란 "연습 모드" 띠가 보이면 성공입니다.

- **여러 명인 것처럼 시험하기**: 일반 창 1개(사회자) + 시크릿 창이나 다른 브라우저(학생)를 여러 개 엽니다. 같은 브라우저의 일반 창끼리는 같은 사람으로 취급됩니다.
- **휴대폰으로 시험하기**: 컴퓨터와 같은 와이파이에 연결한 뒤 `http://컴퓨터의_IP주소:5173` 으로 접속합니다. (학교 와이파이는 기기끼리의 연결을 막아 둔 경우가 있어 안 될 수 있습니다.)
- 연습 모드의 데이터는 에뮬레이터를 끄면(Ctrl+C) 모두 사라집니다.
- <http://localhost:4000> 에서 저장된 데이터를 구경할 수 있습니다.

## 4. 실제로 배포하기 (무료 Spark 요금제)

친구들이 각자 휴대폰으로 접속하려면 실제 Firebase 프로젝트에 올려야 합니다. 한 번만 하면 됩니다.

### 4-1. Firebase 콘솔에서 할 일

1. <https://console.firebase.google.com> 에 구글 계정으로 들어가 **프로젝트 만들기**를 누릅니다. (Google 애널리틱스는 꺼도 됩니다.)
2. **익명 로그인 켜기**: 왼쪽 메뉴 **빌드 → Authentication → 시작하기 → 로그인 방법** 탭 → **익명** → 사용 설정 → 저장.
3. **Firestore 만들기**: 왼쪽 메뉴 **빌드 → Firestore Database → 데이터베이스 만들기**.
   위치는 `asia-northeast3 (서울)`을 고르고, 모드는 **프로덕션 모드**로 시작합니다. (규칙은 아래 4-3에서 올립니다.)
4. **웹 앱 등록**: 프로젝트 개요 옆 **톱니바퀴 → 프로젝트 설정 → 일반** 탭 맨 아래 **내 앱**에서 **웹 아이콘(`</>`)** 을 누릅니다.
   앱 닉네임을 적고 등록하면 아래와 같은 `firebaseConfig` 가 나옵니다.

### 4-2. 설정 값 붙여 넣기

`public/firebase-config.js` 파일을 열어 `여기에_붙여넣기` 자리를 콘솔에 나온 값으로 바꿉니다.

```js
export const firebaseConfig = {
  apiKey: "AIza...",
  authDomain: "내프로젝트.firebaseapp.com",
  projectId: "내프로젝트",
  storageBucket: "내프로젝트.firebasestorage.app",
  messagingSenderId: "1234567890",
  appId: "1:1234567890:web:abcdef",
};
```

> 이 값들은 비밀번호가 아니라서 공개되어도 괜찮습니다. 데이터는 `firestore.rules`(보안 규칙)가 지킵니다.

### 4-3. 규칙과 화면 올리기

```bash
npx firebase login                # 브라우저가 열리면 구글 계정으로 로그인
npx firebase use --add            # 방금 만든 프로젝트를 고르고, 별명은 default 라고 입력
npm run deploy                    # 보안 규칙 + 웹 화면을 올립니다
```

끝나면 `Hosting URL: https://내프로젝트.web.app` 이 나옵니다. 이 주소가 우리 반 회의 주소입니다.

- **꼭 `npm run deploy` 로 규칙까지 함께 올려 주세요.** 규칙이 올라가지 않으면 앱이 "지금은 할 수 없는 동작"이라고만 나옵니다.
- 코드를 고친 뒤에는 `npm run deploy` 를 다시 실행하면 됩니다.
- 설정을 채운 뒤에도 연습 모드로 열고 싶으면 `npm run dev` 후 <http://localhost:5173/?emulator=1> 로 접속합니다.

### 문제가 생기면

| 화면에 나오는 말 | 확인할 것 |
| --- | --- |
| "아직 Firebase 설정이 비어 있어요" | `public/firebase-config.js` 를 채우고 다시 배포했는지 |
| "연결하지 못했어요" (익명 로그인 안내) | 4-1의 2번, 익명 로그인을 켰는지 |
| "지금은 할 수 없는 동작이에요" | 4-1의 3번 Firestore 를 만들었는지, `npm run deploy` 로 규칙을 올렸는지 |
| `npm run dev` 가 바로 꺼짐 | Java 21 이상인지(`java -version`), 5173·8080·9099 포트를 다른 프로그램이 쓰고 있지 않은지 |

## 5. 익명과 공정함은 어떻게 지켜지나요

화면에서 숨기는 것만으로는 조금만 아는 사람이 개발자 도구로 볼 수 있습니다.
그래서 약속들을 서버의 **Firestore 보안 규칙**(`firestore.rules`)으로 막아 두었습니다.

- 마감 전에는 **누구도**(사회자 포함) 남의 의견을 읽을 수 없습니다.
- 투표 중에는 **누구도**(사회자 포함) 남의 투표 용지를 읽을 수 없습니다. 결과 단계가 되어야 용지가 공개되고, 각자 기기에서 직접 집계합니다. 그래서 사회자가 득표 수를 고칠 수도 없습니다.
- 의견과 투표는 한 사람당 하나만 만들 수 있고, 투표는 고치거나 지울 수 없습니다.
- 단계를 바꾸는 것은 사회자만, 정해진 순서(쓰기 → 공개 → 투표 → 결과)로만 할 수 있습니다. 되돌릴 수 없습니다.
- 투표가 시작되면 사회자도 의견 카드를 바꿀 수 없습니다.
- 의견과 투표 용지는 참여자 번호(uid)가 아니라 **본인만 아는 무작위 열쇠**를 이름으로 저장됩니다. 공개된 카드와 용지에는 누구 것인지 알 수 있는 정보가 없고, 의견 원본은 공개되는 순간 지워집니다.

**데이터 구조** (`meetings/{참여 코드}` 아래)

| 위치 | 내용 | 읽을 수 있는 사람 |
| --- | --- | --- |
| `meetings/{code}` | 안건, 단계, 표 수, 잠금, 타이머 | 코드를 아는 사람 |
| `members/{uid}` | 제출했는지·투표했는지 여부만 | 모두 (인원 수 표시용) |
| `secrets/{uid}` | 내 의견 열쇠·투표 열쇠 | 본인만 |
| `opinions/{의견 열쇠}` | 마감 전 의견 | 본인만 / 마감 후 사회자 기기가 카드로 옮기고 삭제 |
| `cards/{id}` | 공개된 의견 카드(묶음 포함) | 마감 후 모두 |
| `votes/{투표 열쇠}` | 고른 카드 목록 | 투표 중에는 본인만 / 결과 단계에 모두 |

## 6. 알려진 한계

한 교실에서 쓰는 수준으로 단순하게 만들어서 아래와 같은 한계가 있습니다.

- **한 사람이 여러 번 참여하는 것을 완전히 막지는 못합니다.** 로그인이 없어서 시크릿 창이나 다른 기기로 들어오면 다른 사람으로 취급됩니다. 참여 인원 수를 반 인원과 비교하고, 다 들어오면 **입장 잠그기**를 켜 주세요.
- **사회자는 회의를 만든 그 기기·그 브라우저에서만 사회를 볼 수 있습니다.** 브라우저 데이터를 지우거나 다른 기기로 옮기면 사회자 권한을 잃습니다. 시크릿 창으로 회의를 만들지 마세요. 학생도 마찬가지로 브라우저 데이터를 지우면 새 참여자가 됩니다.
- **마감 순간 사회자 기기가 켜져 있어야 합니다.** 서버 프로그램 없이(무료 요금제) 만들었기 때문에, 의견을 섞어 공개하는 일은 사회자 기기가 합니다. 중간에 끊기면 사회자가 다시 들어왔을 때 이어서 공개됩니다.
- **사회자는 진행자로서 믿어야 하는 부분이 있습니다.** 의견을 가리거나 묶음의 대표 문장을 정할 수 있습니다. 대신 가린 개수와 묶인 원래 의견은 모두에게 보입니다.
- **Firebase 프로젝트 주인은 콘솔에서 저장된 데이터를 볼 수 있습니다.** 이름은 어디에도 저장되지 않지만, 마감 전 의견 내용 자체는 콘솔에 보입니다. 프로젝트는 믿을 수 있는 사람(선생님 등)이 관리해 주세요. 또 기술을 아주 잘 아는 참여자가 제출·투표 시각을 꼼꼼히 대조하면 추측할 여지가 조금은 남습니다. 완벽한 비밀 투표 시스템은 아닙니다.
- **마감·되돌리기**: 한 번 마감하거나 투표를 시작하면 되돌릴 수 없습니다. 재투표(결선 투표)는 새 회의를 만들어 진행하세요.
- **지난 회의는 자동으로 지워지지 않습니다.** 쌓인 데이터는 Firebase 콘솔의 Firestore 화면에서 `meetings` 를 지우면 됩니다.
- **참여 코드를 아는 사람은 누구나 들어올 수 있습니다.** 코드는 우리 반에만 알려 주세요.
- 타이머는 각 기기의 시계를 기준으로 표시되어 몇 초 정도 차이 날 수 있고, 시간이 끝나도 자동으로 마감되지는 않습니다(사회자가 마감).
- 의견은 200자, 안건은 120자까지입니다. 무료 요금제 한도(하루 읽기 5만 회 등)는 한 반이 쓰기에는 충분합니다.
- 인터넷이 필요합니다. 화면을 그리는 Firebase 라이브러리를 구글 서버(`www.gstatic.com`)에서 불러오므로, 이 주소가 막힌 네트워크에서는 동작하지 않습니다.

## 7. 파일 구성

```
public/
  index.html            화면 틀
  styles.css            디자인 (휴대폰 기준)
  firebase-config.js    ← 내 Firebase 설정을 붙여 넣는 곳
  js/app.js             화면 그리기, 버튼 처리
  js/db.js              Firebase(익명 로그인·Firestore)와 주고받는 부분
  vendor/qrcode.js      QR 코드 그리기 (qrcode-generator, MIT 라이선스)
firestore.rules         보안 규칙 (익명·공정 약속을 서버에서 지킴)
firebase.json           호스팅·에뮬레이터 설정
package.json            실행 명령 (npm run dev / npm run deploy)
```

빌드 과정이 없는 순수 HTML·CSS·JavaScript 라서, 파일을 고치고 새로고침하면 바로 반영됩니다.
