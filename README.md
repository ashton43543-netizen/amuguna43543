# 🗳️ 우리반 회의

**먼저 각자 익명으로 쓰고, 한꺼번에 공개한 다음 투표하는** 고등학교 학급회의용 웹 프로그램입니다.

## 왜 만들었나요?

학급회의에서 여러 명이 함께 의견을 내면 처음 나온 의견이나 목소리 큰 학생의 의견 쪽으로 분위기가 쏠립니다.
생각이 다른 학생은 말을 아끼게 되고, 결론이 한쪽으로 치우치게 됩니다.

그래서 이 프로그램은 회의를 이렇게 진행합니다.

1. 다른 사람의 의견을 보기 **전에** 각자 먼저 익명으로 의견을 냅니다.
2. 사회자가 마감하면 모든 의견이 **무작위 순서로 한꺼번에** 공개됩니다.
3. 비슷한 의견을 묶은 뒤 **익명으로 투표**합니다. 투표 중에는 중간 결과를 숨깁니다.
4. 결과를 그래프로 보여 주고, **소수 의견도 함께 기록**합니다.

학생은 휴대폰으로 **로그인 없이 6자리 참여 코드(또는 QR)** 만으로 참여합니다.

## 기능

### 요청한 기능

| 기능 | 설명 |
| --- | --- |
| 회의 만들기 | 사회자(선생님·반장)가 안건을 입력하면 6자리 참여 코드가 생깁니다. |
| 익명 의견 제출 | 학생은 코드로 입장해 의견을 적습니다. 마감 전에는 다른 학생의 의견이 보이지 않습니다. |
| 동시 공개 | 사회자가 마감하면 모든 의견이 무작위 순서로 한꺼번에 공개됩니다. 먼저 낸 의견이 유리하지 않습니다. |
| 비슷한 의견 묶기 | 사회자가 겹치는 의견을 골라 하나로 합치고 대표 문장을 정합니다. 묶음은 다시 풀 수 있습니다. |
| 익명 투표 | 1인당 1~3표 중에서 정할 수 있습니다. 투표가 끝날 때까지 중간 결과는 아무도 볼 수 없습니다. |
| 결과 화면 | 득표 결과를 막대그래프로 보여 주고, 소수 의견을 따로 모아 보여 줍니다. |

### 더 넣은 기능

쏠림을 줄이고 진행을 편하게 하려고 아래 기능을 더 넣었습니다.

- **🔒 사회자도 마감 전에는 의견을 볼 수 없음**: 화면에서만 숨기는 게 아니라 Firebase 보안 규칙이 서버에서 막습니다. 휴대폰 개발자 도구로 몰래 열어 볼 수도 없습니다.
- **🔀 학생마다 투표 순서를 다르게 섞기**: 목록 맨 위에 있는 의견이 표를 더 받는 현상(순서 효과)을 줄입니다.
- **🙈 투표할 때는 묶음 크기 숨기기**: 투표 화면에는 "비슷한 의견 5개"처럼 몇 명이 같은 생각을 했는지 보여 주지 않아서, 많은 쪽을 따라가는 효과를 줄입니다. 공개 단계와 결과 화면에서는 보여 줍니다.
- **💬 "이유" 칸**: 의견과 함께 그렇게 생각한 이유를 적을 수 있습니다(선택). 소수 의견도 이유가 함께 남습니다.
- **📊 제출 인원 실시간 표시**: 내용은 숨긴 채 "18 / 28명 제출"처럼 몇 명이 냈는지만 보여 줍니다. 참여 인원을 입력하면 진행 막대도 나옵니다.
- **⏱ 타이머**: 3분, 5분, 10분 타이머를 학생 화면에도 함께 보여 줍니다. 마감은 사회자가 직접 합니다.
- **📱 QR 코드 입장**: 칠판이나 TV에 사회자 화면을 띄우면 학생들이 QR로 바로 들어옵니다.
- **✏️ 마감 전 의견 수정**: 학생은 마감 전까지 자기 의견을 고칠 수 있습니다.
- **🚫 부적절한 의견 숨기기**: 특정 친구를 비난하는 글 등은 사회자가 숨길 수 있습니다. 숨긴 의견은 투표에 나오지 않습니다.
- **🌱 소수 의견 기록**: 1위 득표의 절반 이하를 받은 의견(0표 포함)을 이유와 함께 따로 보여 줍니다.
- **📝 회의 결론 및 회의록 복사**: 사회자가 결론을 적으면 학생 화면에도 나타납니다. "회의록 복사" 버튼은 안건, 결과, 소수 의견, 결론을 글로 정리해 줍니다. 학급 단톡방이나 회의록에 바로 붙여 넣으면 됩니다.

## 회의 진행 순서

| 단계 | 사회자 화면 | 학생 화면 |
| --- | --- | --- |
| ① 각자 쓰기 | 참여 코드·QR, 제출 인원, 타이머 → **[마감하고 한꺼번에 공개하기]** | 의견 + 이유 입력 → 익명 제출 (마감 전 수정 가능) |
| ② 공개·묶기 | 무작위 순서로 공개된 의견 목록. 체크해서 **묶기**, **숨기기**, 1인당 표 수 정하기 → **[익명 투표 시작]** | 공개된 모든 의견 읽기 |
| ③ 익명 투표 | 투표 인원만 표시 (결과는 숨김) → **[투표 마감하고 결과 공개]** | 나만의 순서로 섞인 의견 중에서 골라 투표 (1회) |
| ④ 결과 | 막대그래프, 소수 의견, 결론 입력, 회의록 복사 | 막대그래프, 소수 의견, 결론 |

> 💡 사회자는 회의를 만든 **같은 기기, 같은 브라우저**로 끝까지 진행하세요. 로그인 없이 브라우저마다 익명 ID를 쓰기 때문에, 다른 기기에서는 사회자로 인식되지 않습니다. 같은 브라우저에서는 새로고침하거나 첫 화면의 "내가 만든 회의"를 눌러도 다시 들어갈 수 있습니다.

## 실행 방법

필요한 것은 [Node.js](https://nodejs.org/) 20 이상과 Google 계정입니다. 비용은 들지 않습니다. 한 반이 쓰는 정도는 Firebase 무료(Spark) 요금제로 충분합니다.

### A. 내 컴퓨터에서 먼저 시험해 보기 (Firebase 프로젝트 없이)

Firebase 에뮬레이터로 내 컴퓨터 안에 가짜 서버를 띄워서 시험합니다. 에뮬레이터를 쓰려면 **Java 21 이상**이 설치되어 있어야 합니다.

```bash
npm install
npm run dev
```

`All emulators ready!`가 뜨면 브라우저에서 **http://localhost:5050/?emulator** 를 엽니다.

- 일반 창으로 회의를 만들고(사회자), **시크릿 창**을 여러 개 열어 같은 주소로 들어가면 학생 여러 명처럼 시험할 수 있습니다.
- 주소 끝의 `?emulator`가 있어야 에뮬레이터에 연결됩니다.
- 에뮬레이터를 끄면(Ctrl + C) 데이터는 사라집니다.

### B. 실제로 교실에서 쓰기 (Firebase에 올리기)

#### 1) Firebase 프로젝트 만들기

1. [Firebase 콘솔](https://console.firebase.google.com/)에서 **프로젝트 추가**를 누릅니다. 이름 예: `our-class-meeting`. Google 애널리틱스는 꺼도 됩니다.
2. 왼쪽 메뉴 **빌드 → Authentication → 시작하기 → 로그인 방법** 탭에서 **익명**을 **사용 설정**하고 저장합니다.
3. **빌드 → Firestore Database → 데이터베이스 만들기**를 누릅니다.
   - 위치: `asia-northeast3 (서울)` 추천
   - 모드: **프로덕션 모드**로 시작 (보안 규칙은 다음 단계에서 올립니다)
4. **프로젝트 설정(⚙️) → 일반 → 내 앱**에서 웹 아이콘 `</>`을 눌러 웹 앱을 등록합니다. Hosting 설정 체크는 안 해도 됩니다.
5. 화면에 나온 `firebaseConfig` 값을 복사해서 [`public/firebase-config.js`](public/firebase-config.js)에 붙여 넣습니다.

```js
export const firebaseConfig = {
  apiKey: "AIza....",
  authDomain: "our-class-meeting.firebaseapp.com",
  projectId: "our-class-meeting",
  storageBucket: "our-class-meeting.appspot.com",
  messagingSenderId: "1234567890",
  appId: "1:1234567890:web:abcdef",
};
```

> 이 값들은 웹 주소처럼 공개되어도 괜찮은 정보입니다. 데이터는 `firestore.rules` 보안 규칙이 지킵니다.

#### 2) 보안 규칙과 웹사이트 올리기

```bash
npm install            # 처음 한 번만
npx firebase login     # Google 계정으로 로그인
npx firebase use --add # 방금 만든 프로젝트 선택 (별칭은 default)
npm run deploy         # 보안 규칙 + 웹사이트 배포
```

배포가 끝나면 `https://<프로젝트ID>.web.app` 주소가 나옵니다. 이 주소를 칠판에 적거나 TV에 띄우면 됩니다.
사회자가 회의를 만들면 화면에 참여 코드와 QR 코드가 크게 나옵니다.

> ⚠️ **보안 규칙은 꼭 배포하세요.** 규칙을 올리지 않으면 "마감 전 비공개, 중간 결과 숨김, 1인 1회 투표"가 지켜지지 않습니다.
> 명령어 대신 Firebase 콘솔의 **Firestore Database → 규칙** 탭에 [`firestore.rules`](firestore.rules) 내용을 통째로 붙여 넣고 **게시**해도 됩니다.

#### (선택) 배포 없이 내 컴퓨터에서 실제 프로젝트로 띄우기

```bash
npx firebase emulators:start --only hosting
```

이렇게 하면 http://localhost:5050 에서 화면 파일만 내 컴퓨터가 보여 주고, 데이터는 실제 Firebase 프로젝트에 저장됩니다. 이때 주소에 `?emulator`를 붙이지 않습니다.
같은 와이파이의 휴대폰으로 접속하려면 배포(B-2)하는 편이 훨씬 간단합니다.

## 파일 구조

```
├── public/                  # 웹사이트 (빌드 과정 없음. HTML/CSS/JS 그대로)
│   ├── index.html
│   ├── style.css            # 모바일 우선 화면 디자인 (다크 모드 지원)
│   ├── app.js               # 화면과 동작 전부
│   └── firebase-config.js   # ← 내 Firebase 설정값을 넣는 곳
├── firestore.rules          # 보안 규칙 (익명성, 비공개, 1인 1회를 서버에서 강제)
├── firebase.json            # Firebase Hosting/에뮬레이터 설정
└── package.json             # npm run dev / npm run deploy
```

## 데이터 구조와 익명성은 어떻게 지켜지나요?

```
meetings/{참여코드}           안건, 단계(phase), 1인당 표 수, 제출·투표 인원 수, 결론
  ├─ opinions/{익명ID}        원본 의견 (1인 1개)
  ├─ cards/{무작위ID}         공개용 의견 카드 (작성자 정보 없음, 무작위 순서)
  └─ votes/{익명ID}           투표 (1인 1회)
```

- **이름이나 학번을 받지 않습니다.** 학생은 브라우저마다 자동으로 만들어지는 익명 ID(Firebase 익명 로그인)로만 구분됩니다.
- **마감 전**(`collect` 단계)에는 보안 규칙상 자기 의견만 읽을 수 있습니다. 사회자도 다른 사람 의견을 못 봅니다.
- 마감하면 사회자 화면이 원본 의견을 **섞은 뒤, 작성자 ID를 뺀 공개용 카드**로 옮깁니다. 학생들은 이 카드만 봅니다.
- **투표 중**(`vote` 단계)에는 자기 투표만 읽을 수 있어서, 누구도 중간 결과를 알 수 없습니다.
- 의견과 투표 문서는 익명 ID를 문서 이름으로 쓰기 때문에 **1인 1의견, 1인 1회 투표**가 서버에서 강제됩니다.
- 제출·투표 인원 수는 실제로 의견이나 투표 문서를 만들 때만 1씩 올라가도록 규칙으로 묶여 있습니다. 숫자만 따로 부풀릴 수 없습니다.

## 알아 둘 점 (한 교실용 단순 버전의 한계)

- **시크릿 창이나 다른 브라우저로 다시 들어오면 새 익명 사용자로 인식됩니다.** 마음먹으면 한 사람이 여러 번 참여할 수 있습니다. 회의를 만들 때 **참여 인원**을 입력해 두면 "31 / 28명"처럼 이상한 숫자가 바로 보이니 확인용으로 쓰세요.
- 사회자 권한은 회의를 만든 브라우저에만 있습니다(위의 💡 참고).
- 지난 회의 데이터는 Firebase 콘솔의 **Firestore Database → 데이터**에서 `meetings` 아래 문서를 지우면 정리됩니다.
- 학생 휴대폰은 인터넷에 연결되어 있어야 합니다(학교 와이파이 또는 데이터).

## 나중에 더 해 볼 만한 것

- 선생님 계정 로그인으로 여러 기기에서 사회자 진행
- 반 전체 명단 기반 참여 확인(익명은 유지하면서 1인 1회만 확인)
- 지난 회의 결과 모아 보기, 결정 사항 실행 점검
- 찬반이 갈릴 때 쓰는 "반대 의견 먼저 듣기" 단계
